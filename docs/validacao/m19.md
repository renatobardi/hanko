## Env e flags novas

Nenhuma. O registro do webhook do Telegram usa a `HANKO_PUBLIC_URL` existente (https). CLI nova: `hanko channel add|list|show|edit|enable|disable|rm|connect|link|unlink|messages|resend|send|review`, `hanko flow trigger|var|edit|archive|unarchive|revisions|restore`.

## Como validar no hanko-prd

Pré-requisitos: `HANKO_PUBLIC_URL` https alcançável pelo Telegram/GitHub, `HANKO_SECRET_KEY` definida (segredos).

1. **Fluxo com variáveis e webhook.**
   ```
   hanko flow create "Revisar PR" -p ada --var repo! --title 'Revisar {{repo}}'
   hanko flow trigger add revisar-pr github --kind webhook --map repo=repository.full_name
   ```
   Guarde o segredo mostrado (uma vez). Entrega assinada: ver o exemplo no RUNBOOK (seção "Fluxos: variáveis, gatilhos…"). Esperado: `202` com `task_key`; repetir com o mesmo `X-Hanko-Delivery` dá `200` `duplicate`; assinatura errada `401`; sem `repo` `422`.
2. **Evento interno.** `hanko flow trigger add <fluxo> ao-decidir --kind event --event 'gate.*'`; decida um gate e confira a task nova no fluxo (`hanko flow show`).
3. **Revisões/arquivar.** `hanko flow edit … ` duas vezes; `hanko flow revisions`; `hanko flow restore <fluxo> 1`; `hanko flow archive` e confirmar `409` no webhook.
4. **Telegram.** Segredos `tg-token` (BotFather) e `tg-hook` (qualquer valor aleatório). `hanko channel add bot --kind telegram -p ada --token '${secret:tg-token}' --webhook-secret '${secret:tg-hook}' --enable`; `hanko channel connect bot`; `hanko channel link bot` e enviar `/vincular CODIGO` ao bot. Esperado: "Vinculado a …". Criar um gate (`approval`) e decidir pelo botão; a atividade do gate mostra a pessoa vinculada como autora. Texto livre vira conversa com a persona; a resposta volta ao chat.
5. **GitHub.** `hanko channel add gh --kind github -p ada --token '${secret:gh-token}' --webhook-secret '${secret:gh-hook}' --repo <dono>/<repo> --enable`; webhook no repositório para `<HANKO_PUBLIC_URL>/hooks/channels/<identificador>` com os eventos de comentário/review; vincular com um comentário `/hanko vincular CODIGO`; depois comentar no PR citando a menção do canal. Esperado: task criada para a persona e resumo publicado no PR; `hanko channel review gh --task … --event comment --body …` publica uma review (APPROVE exige admin humano).
6. **Respostas rápidas.** Ligar a feature *fast_response* no decision model e perguntar "quantas tasks abertas?" no Telegram: resposta imediata, sem acordar a persona (atividade `channel.reply_fast`).

## Riscos

- Entrega do Telegram é pelo menos uma vez; uma falha entre o envio e o registro pode duplicar uma mensagem.
- O bucket de limite por gatilho vive no banco (uma escrita por entrega); rajadas grandes são limitadas por IP antes (`ratelimit.webhooks_per_min`).
- Gatilho por evento roda na transação do fato: um filtro mal escrito só descarta, nunca desfaz o fato original.
- O comportamento real do Telegram/GitHub (formato de payload em produção, limites de taxa deles) só foi exercitado por fakes.

## Pulado/Falhou

- Sem validação contra Telegram ou GitHub reais (fora do escopo: sem tokens).
- Gates de tipos `question`, `plan`, contratação e instrução não têm botão no Telegram (resumo + link).
- Gatilhos não são exportados/importados (por desenho; segredos não viajam).
