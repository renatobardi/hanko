Branch `evolucao/m13` · banco de teste `hanko_test_m13` · migration `00090_resiliencia_run.sql`.

## O que entrou
- **#12 Continuação limitada.** `runs.continuation_of_run_id/continuation_attempt/continuation_reason` (+ `resume_pending/resume_reason`).
  Run interrompida (queda do processo no boot, ou encerramento do servidor) → diagnóstico + continuação automática, máx. 2.
  `session_ref` gravado na hora (`adapter.Event.SessionRef`). Briefing no prompt (`internal/heartbeat/continuation.go`).
- **#13 Card de diagnóstico e ações.** `runs.diagnosis` (jsonb), `decision_pending/decision/decision_note`. Tool de efeito externo em
  andamento ao morrer (`domain.OpenToolCalls` + `ToolHasExternalEffect`) → "desfecho incerto" → decisão humana. API
  `POST /runs/{id}/actions`; CLI `hanko run retry|continue|close`; UI na run e na Caixa.
- **#14 Steer por capability.** `adapter.Steerer` / `domain.SteerModeFor`: claude (stdin `--input-format stream-json`), acp
  (`session/cancel` + novo `session/prompt` na mesma sessão), fake (injeta no laço) e codex (interromper e continuar). API
  `POST /runs/{id}/steer`; CLI `hanko run steer`; UI mostra o modo.
- **#15 Fila de follow-ups.** Tabela `task_followups` + `conversation_messages.edited_at/delivery`; visão única `domain.Followup`.
  API `GET|POST /tasks/{t}/followups`, `GET /conversations/{c}/followups`, `PATCH|DELETE /followups/{id}`; CLI `hanko followup`; UI
  (painel na task e no chat). Cancelar dispara o próximo run com os pendentes.

## Como validar no hanko-prd
1. `hanko migrate` (aplica a 00090). Sem env/flags novas.
2. **Matar o processo no meio:** com uma task em andamento (`hanko run list --status running`), `kill -9` do servidor e suba de novo.
   Esperado: `hanko run list --task <chave>` mostra a run `interrupted` e uma nova run com `continuation_of_run_id`; `hanko run show
   <nova>` indica "Continuação de …"; o log da nova run traz a sessão retomada (claude) e o prompt tem a seção "Continuação de uma
   execução anterior".
3. **Desfecho incerto:** mate o servidor enquanto o agente executa um `Bash` (ex.: um `sleep 60` ou `git push`). Esperado: nenhuma
   run nova; Caixa > Falhas > "Execuções paradas esperando decisão" com a tool; `hanko run continue <run> --note …` abre a continuação.
4. **Esgotar:** repita a queda 3 vezes seguidas na mesma cadeia: a terceira vai para a Caixa (card "as 2 continuações automáticas já foram usadas").
5. **Steer:** numa run ativa de claude, `hanko run steer <run> "foque nos testes"` (UI: caixa "Mudar o rumo", modo "injeta ao vivo");
   o log mostra "mensagem do operador injetada" e o comentário aparece na task. Numa run de codex o modo é "interrompe e continua".
6. **Fila:** durante uma run, `hanko followup add --task <chave> "..."`, `hanko followup list --task <chave>` (ordem e motivo),
   `edit`/`discard`; ao fim da run a seguinte recolhe os pendentes. No chat, mande 2 mensagens com a persona respondendo, cancele a run:
   a seguinte abre com as pendentes.

Testes que provam a demo (adapter fake): `TestKilledRunContinuesOnItsOwn`, `TestKilledRunWithUncertainOutcomeWaitsForHuman`,
`TestSteerChangesTheCourseOfTheActiveRun`, `TestSteerRestartsAHarnessWithoutInjection` (`internal/heartbeat`, tag `integration`).

## Riscos
- `claude` em stream-json multi-turno: o `result` de cada turno repete custo/uso acumulado da sessão; o Hanko fica com o último
  (custo pode ser subcontado só se o harness reportar por turno). Nunca testado contra o binário real (sem rede/custo): coberto por
  script de harness falso (`internal/adapter/claude/testdata/fake-claude-steer.sh`) e testes do encoder.
- ACP não tem injeção padronizada: o modo `inject` do ACP é cancelar o turno e reenviar na mesma sessão (pode abortar a tool em curso do agente).
- A lista de tools "de leitura" (`domain.readOnlyTools`) é uma allowlist manual e conservadora: tool desconhecida conta como efeito externo.
- Codex não retoma sessão aqui (sem `SessionResumer`): a continuação dele só leva o briefing.
- Um wake que coalesce num job de wake ainda rodando pode se perder (limitação anterior do heartbeat); a rede de segurança
  (follow-up parado > 1 min, `resume_pending` > 1 min) o recupera no tick seguinte.

## Pulado/Falhou
Nada pulado. Pendências conscientes: MCP não expõe as ações novas (fora do escopo do marco); conversa arquivada não retoma run
interrompida (aviso na conversa, decisão humana).
