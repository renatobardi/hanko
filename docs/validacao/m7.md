## Como validar no hanko-prd

Pré-requisito: `HANKO_SECRET_KEY` definida (32+ bytes; `openssl rand -hex 32`) e `docker compose up -d` com o binário novo (a migration roda no boot).

1. **O env antigo migra cifrado.** No log do boot: `segredos: env das personas movido para segredos cifrados personas=N`. Conferir:
   `psql -c "select slug, adapter_config->'env' from personas where adapter_config ? 'env'"` deve mostrar só `${secret:persona.<slug>.<VAR>}`;
   `hanko secret ls` lista os segredos `persona.*`. Sem a chave, o boot avisa e nada muda.
2. **Persona usa um segredo por referência.**
   ```
   printf '%s' "$TOKEN" | hanko -c acme secret create gateway-token --value-stdin
   hanko -c acme persona hire "Ana" --agent claude --config-json '{"env":{"ANTHROPIC_AUTH_TOKEN":"${secret:gateway-token}"}}'
   hanko -c acme secret show gateway-token        # "usado por: persona:ana"; nunca o valor
   ```
   Abrir uma task para a Ana: a execução recebe o token (o harness autentica), e o log da execução (`/c/acme/execucoes/…`) não contém o
   valor. `hanko secret rotate gateway-token --value-stdin` e uma nova execução já usa o valor novo.
3. **Revelar uma vez.** `hanko secret reveal gateway-token` mostra o valor; repetir devolve 409 até `rotate`. Tela: Configurações › Segredos › Ações.
4. **Artefato vai para o S3.** Com um MinIO/S3 de teste: `HANKO_BLOB_DRIVER=s3 HANKO_S3_ENDPOINT=… HANKO_S3_BUCKET=… HANKO_S3_ACCESS_KEY=… HANKO_S3_SECRET_KEY=…`,
   reiniciar, `hanko artifact put relatorio.md --task HNK-1`; o objeto aparece em `<prefixo>/<empresa>/<artefato>` no bucket e
   Configurações › Instância › Armazenamento mostra `s3` ativo. Migrar o legado: `hanko blobs migrate --from postgres --to s3 --dry-run`, depois sem `--dry-run`
   (o `pg_dump` encolhe).
5. **Settings.** Configurações › Instância (dono da instalação): ligar `integrations.allow_stdio` e criar uma integração stdio sem reiniciar;
   com `HANKO_ACP_ALLOW` definida no ambiente, `acp.allow` aparece "travada por HANKO_ACP_ALLOW" e a API devolve 409.
6. **Cofre externo (opcional).** `HANKO_VAULT_ADDR`/`HANKO_VAULT_TOKEN`; `hanko secret create cofre --vault-ref apps/hanko#token`; a persona que referencia `${secret:cofre}` lê o valor do cofre a cada execução.

## Reconciliação com a main (PR #4)

Migrations renumeradas para 00035–00037 e ADRs para 0050 (segredos) e 0051 (BlobStore). `${secret:X}` também vale no env dos ambientes de
execução (ADR-0037), nos campos secretos de plugins (ADR-0038) e nos headers de integrações MCP http pelo gateway de tools (ADR-0036); o
rekey cobre `secrets`, integrações, plugins e ambientes.

## Riscos e decisões a conhecer

- **Backup com S3:** o `pg_dump` deixa de cobrir os arquivos que estão no bucket; o bucket precisa de backup próprio (RUNBOOK).
- **Objetos órfãos no S3** (processo morto entre o upload e a transação, falha ao apagar, empresa apagada) não aparecem na cota; não há `blobs gc` ainda (a chave é determinística).
- **Apagar um segredo em uso** quebra a execução da persona no próximo despacho (falha cedo, com o nome do segredo); a integração MCP é pulada com aviso.
- **Admin e segredos:** quem define o `adapter_config` de uma persona consegue fazê-la usar o segredo; "revelar uma vez" é auditoria, não barreira (ADR-0050 §11).
- A migração do env das personas roda no boot; é idempotente, mas altera `personas.adapter_config` (uma atividade `persona.env_migrated` por persona).
- `gofmt -l` aponta `internal/i18n/en.go`, `en_cli.go`, `en_ds.go`, `en_skills.go` (alinhamento de mapas, anterior ao M7 e do gofmt do Go 1.27); não foram tocados para não gerar conflito.

## Pulado/Falhou

- **Segredos de usuário em execuções de persona:** não há como registrar "o humano que pediu a run" (`runs` não tem o solicitante); entregue o armazenamento, a privacidade, a revelação e `ResolveUserSecretText` para ações do próprio dono. O uso por runs fica para quando a run registrar o solicitante.
- **Credencial de repositório (#33) e provider de modelo próprio (#27):** esses recursos ainda não existem no código; entreguei o ponto de entrada `Service.ResolveSecretText` (e o `env` da persona, que hoje é o provider de modelo, já usa referência). Quando #33/#27 chegarem, só chamam o resolvedor.
- **Flags experimentais em `instance_settings`:** o grupo `experimental.*` existe no registro, mas nenhum flag foi criado (não há feature experimental ainda).
- **Tool MCP de segredos:** não criada de propósito; um agente não deve gerenciar nem ler segredos (o service recusa atores persona). Os cuidados de não-vazamento foram implementados e testados.
