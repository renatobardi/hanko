### Banco do prd num Postgres compartilhado (schema `hanko_prd`)

- O `docker-compose.yml` lê a `HANKO_DATABASE_URL` do `.env`; o Postgres próprio passa para o profile opcional `localdb`, que o `deploy-prd.sh` liga sozinho quando a URL aponta para `@postgres` ou não existe. O Hanko deixa de montar o volume do banco e o alerta `db_disk_low` não é avaliado no prd (ADR-0092).
- `hanko backup` cobre só o schema corrente da conexão e grava `db_schema` no manifest; o restore esvazia esse schema e recria tudo numa transação, em vez de apagar e recriar `public`, e recusa backup de outro schema. `hanko backup create` e `verify` mostram o schema do banco.
- `backup.sh` e `restore.sh` funcionam com banco externo: clientes num contêiner descartável `postgres:17`, conexão só em variáveis `PG*`, dump do schema corrente, `pre-restore-<ts>.pgdump` antes de restaurar e aplicação numa transação.

- English summary: `docker-compose.yml` now reads `HANKO_DATABASE_URL` from `.env`; the bundled Postgres moves to the optional `localdb` profile, which `deploy-prd.sh` enables when the URL points at `@postgres` or is missing. Hanko no longer mounts the database volume and `db_disk_low` is not evaluated in production (ADR-0092). `hanko backup` covers only the connection's current schema and records `db_schema` in the manifest; restore empties that schema and recreates everything in one transaction instead of dropping and recreating `public`, and refuses a backup from another schema. `backup.sh` and `restore.sh` support an external database through a throwaway `postgres:17` client container, with the connection only in `PG*` variables.
